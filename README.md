# СТЫК ↗

**Вещи сходятся.** Маркетплейс с собственным визуальным стилем, Java-бэкендом и автоматизацией складской логистики.

React · JavaScript · Java 21 · Spring Boot · Spring Security · JPA / Hibernate · PostgreSQL · Flyway · Docker Compose

## Возможности

- Каталог из 12 демонстрационных товаров: поиск, категории, цена, скидки, сортировка и карточки.
- Гостевая корзина с переносом в аккаунт, серверная корзина, избранное и отзывы после доставки.
- Оформление заказа, промокод `STYK10`, демонстрационная оплата, история, отмена и возврат.
- Кабинет продавца: создание и редактирование карточек с модерацией, заявки на поставку, подтверждение и отправка.
- Склад: резервы, сборка, упаковка, отгрузка, приёмка с расхождениями, ячейки хранения и журнал движений.
- Автопополнение: минимальный и целевой остаток, простой прогноз по продажам, вычет товаров в пути.
- Админка: оборот, заказы, популярные товары, модерация, роли, блокировка пользователей и аудит.
- Серверная сессия, BCrypt, CSRF, актуализация прав на каждом запросе и SQL-блокировки остатков.

## Быстрый запуск

Требуется Docker с Compose:

```sh
cp .env.example .env
docker compose up --build
```

Откройте **http://localhost:8088**. Первый запуск загружает образы и собирает приложения. PostgreSQL сохраняет данные в именованном томе `styk-data`; обычная остановка данные не удаляет.

### Демонстрационные аккаунты

Общий пароль из `.env`: `StykDemo2026!`.

| Роль | Почта |
|---|---|
| Покупатель | buyer@styk.local |
| Продавец «Бюро предметов» | seller@styk.local |
| Продавец «Студия Формы» | studio@styk.local |
| Сотрудник склада | warehouse@styk.local |
| Администратор | admin@styk.local |

Это локальные учебные аккаунты. Для внешнего развёртывания отключите `DEMO_SEED`, задайте собственные учётные записи и секреты, настройте HTTPS и `COOKIE_SECURE=true`. Изменение `DEMO_PASSWORD` не перезаписывает пароли уже созданных пользователей.

### Без Docker

Требуются JDK 21+, Maven 3.9+ и Node.js 22+.

```sh
cd backend
mvn package
java -jar target/marketplace-1.0.0.jar --spring.profiles.active=local
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Интерфейс: **http://127.0.0.1:5173**. Java API: **http://127.0.0.1:8091/api/health**. Локальный профиль использует файловую H2 в режиме совместимости PostgreSQL, данные находятся в `backend/data/`. По умолчанию Vite проксирует `/api` на порт 8091; для другого адреса задайте `API_TARGET`.

## Проверки

```sh
mvn -B -f backend/pom.xml verify
cd frontend
npm ci
npm run build
```

12 интеграционных сценариев проверяют резервирование, отмену, возврат, конкурентную покупку последнего товара, откат неудачного заказа, повторное оформление, пополнение с учётом входящих поставок, повторную приёмку, чужие поставки, недопустимые статусы, CSRF и права доступа.

GitHub Actions запускает тот же набор на H2 и настоящем PostgreSQL 17, а также собирает интерфейс. Локально PostgreSQL-набор пропускается, если не задан `TEST_POSTGRES_URL`.

## Демонстрация за 5 минут

1. Добавьте наушники в корзину гостем. Войдите покупателем — корзина переносится в аккаунт.
2. Оформите заказ с тестовым адресом и промокодом `STYK10`. В заказах появится резерв.
3. Войдите сотрудником склада. На вкладке «Заказы» пройдите сборку → упаковку → отгрузку → доставку.
4. На вкладке «Остатки» проверьте изменение количества. «Движения» покажут резерв и списание.
5. Нажмите «Пополнить запасы» или дождитесь планировщика. Для наушников с низким остатком создастся заявка.
6. Войдите продавцом: подтвердите поставку и отправьте её.
7. Войдите сотрудником склада: примите поставку, при расхождении укажите фактическое количество и причину.
8. Войдите администратором: откройте показатели, модерацию и управление пользователями.

## Границы версии

Один склад, несколько продавцов, один SKU на карточку. Оплата и доставка моделируются внутри приложения: деньги не списываются, внешние перевозчики не вызываются. Нет фискализации, выплат продавцам и автоматической компенсации повреждённых товаров. Приёмка фиксирует расхождения и приходует только принятое количество.

Поиск и фильтры выполняются в браузере для небольшого каталога. Перед ростом каталога нужны серверная пагинация и поиск. Изображения — собственные SVG или HTTPS-ссылки продавца; файлового S3-хранилища пока нет. Доставка, уведомления и платежи входят в сценарии заказа и поставки, а не выделены в отдельные сервисы. Рекомендации — редакционная подборка. Возврат доступен для всего заказа.

Шрифты Tektur, Commissioner и IBM Plex Mono загружаются через Google Fonts. При отсутствии сети применяются системные замены. Графика товаров хранится в репозитории.
