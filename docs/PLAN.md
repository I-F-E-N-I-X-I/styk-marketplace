# План разработки STYK

## Продукт
Маркетплейс с одним складом и несколькими продавцами. Четыре роли: покупатель, продавец, сотрудник склада, администратор. Единица каталога — конкретное предложение продавца с уникальным SKU. Разные цвета и комплектации могут оформляться отдельными SKU; группировка вариантов — следующий этап.

## Этапы и критерии
1. Архитектура: Java 21, Spring Boot, JPA, PostgreSQL, Flyway; React и JavaScript. Локальный H2-профиль для работы без Docker.
2. Визуальная система: кремовый, графит, лайм, терракота; Tektur, Commissioner, IBM Plex Mono; адаптивные страницы и собственные иллюстрации товаров.
3. Идентификация: регистрация покупателей, серверная сессия, BCrypt, CSRF, проверка актуальной роли и блокировки на каждом запросе.
4. Каталог: категории, фильтры, поиск, сортировка, карточка, избранное, отзывы после доставки.
5. Заказ: серверная корзина, повторяемый ключ оформления, актуальные цены, промокод, демонстрационная оплата, резерв и возврат.
6. Логистика: резерв → сборка → упаковка → отгрузка → доставка; заявки продавцам → подтверждение → отправка → приёмка с расхождениями.
7. Автоматизация: периодический расчёт пополнения, учёт открытых поставок и спроса за 14 дней; последовательная блокировка SKU для защиты от дублей.
8. Кабинеты: ассортимент и поставки продавца, склад и журнал движений, модерация, пользователи, аналитика и аудит администратора.
9. Проверки: права доступа, чужие данные, двойное оформление, конкурентное резервирование, отмена, повторная приёмка, расчёт пополнения. Проверка PostgreSQL в CI, сборка фронтенда и ручной просмотр.
10. Публикация: исходники, инструкция, схема архитектуры, сценарий демонстрации и добавление в GitHub-портфолио.

## Инварианты
- 0 ≤ резерв ≤ физический остаток.
- Все изменения остатков проходят транзакционно и сопровождаются движениями.
- При отгрузке уменьшаются физический остаток и резерв; при отмене — только резерв.
- Поставка увеличивает физический остаток только при подтверждённой приёмке.
- Повтор запроса оформления с тем же ключом возвращает прежний заказ.
- Повтор завершённого перехода не списывает и не приходует товар снова.
- Продавец не может редактировать предложения и поставки другого продавца.

## Границы версии
Оплата и доставка демонстрационные. Реальные платёжные и транспортные API, фискализация, выплаты продавцам, несколько складов, загрузка файлов в S3 и полноценный поиск на большом каталоге остаются отдельными интеграциями. В этой версии изображения — статические ресурсы или HTTPS-ссылки. Корзина аккаунта хранится в БД, гостевая — в браузере с объединением после входа.
